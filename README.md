# make-money-test · 轻量付费测试引擎

一套能反复复用的「趣味测试 + 兑换码解锁」小产品：做一次引擎，之后**只换一份内容配置就是一个新商品**。

第一套内容是 **韭菜段位测试**：12 道盘面情境题，测出 6 档韭菜段位（玩梗），再按 MBTI 式的四个维度，匹配 16 位大家都熟悉的历史人物（曹操、诸葛亮、司马懿、李白、刘禅……）作为「人格底色」。

- 段位卡负责被晒、被转发；好友对比负责拉新
- 完整人格报告 7 个板块：四维图谱、人物自画像、财商六维、共同底色、真实故事、盲点与反割建议、搭子与天敌
- 默认「先付费」：开场输兑换码，进来全部可看；也可以切到「先玩后付」
- 兑换码作为虚拟商品在店铺售卖，网站可以纯静态部署，不依赖服务器

## 常用命令

需要 Node 22.13 及以上。

```bash
npm run preview                 # 本地预览 http://localhost:8788/jiucai/（兑换码填 DEMO）
npm run check                   # 改完内容必跑：缺字段、人格 / 段位分布、高危词
npm install && npm run notes    # 生成笔记和商品素材到 out/notes/<id>/（需要本机装有 Chrome）
npm run admin                   # 查看管理命令
npm run build:preview           # 打包静态预览版到 out/preview/（没有后端时输入 DEMO 解锁）
npm run codes:static -- jiucai 500 --prefix JC   # 生成兑换码 + 静态码表（纯静态部署用）
```

## 计分规则

- 每个选项给 4 个维度加减分（`s`），再给两个仪表加分（`m`：上头指数、纪律值）。
- **人格**：4 个维度各取一极，拼成代码，比如「冲独快断」，对应 16 位人物之一。
- **主导维度 / 共同底色**：按各维度的偏向强度排序，最强的是主导维度，前三个分别作为「第一底色 / 隐藏天赋 / 长期优势」。
- **财商六维**：由维度偏向和两个仪表换算，公式在 `config.abilities`。
- **段位**：由 `纪律值 - 上头指数` 决定，阈值写在 `tiers[].min`。
- **匹配度**：取四个维度的偏向强度，映射到 76%～97%。
- **搭子 / 天敌**：搭子是把「风险」和「节奏」两个维度翻转后的人格，天敌是四个维度全部翻转。

每道题在每个维度上的加减分是正负抵消的，所以人格和段位基本互不影响。改题目后跑 `npm run check`：每个人格的随机出现率最好在 2% 以上。

## 付费方式

在 `config.js` 的 `paywall.mode` 里改一个字段即可切换：

| mode | 体验 | 适合 |
|---|---|---|
| `start`（默认） | **先付费**：开场输兑换码，进来后段位、人格、完整报告全部直接看 | 店铺先下单、再拿入口的模式。只有一次付费决策，不会在中途流失 |
| `report` | **先玩后付**：段位卡和四维图谱免费，其余 6 个板块输码解锁 | 链接能自由传播、靠免费部分吸引人的渠道 |
| `none` | 全部免费 | 纯引流 |

## 兑换码：两种校验方式，自动选择

| 方式 | 怎么生成 | 优点 | 代价 |
|---|---|---|---|
| **静态码表**（推荐起步） | `npm run codes:static -- jiucai 500 --prefix JC` | 网站是纯静态文件，**任何地方都能部署**，零维护 | 不能限制一个码用几台设备；新增码要重新部署 `public/` |
| 服务器接口 | 在服务器上运行 `mm gen jiucai 500 --prefix JC` | 一码限 3 台设备、能作废、有转化统计 | 要跑一个 Node 服务 |

页面会自动判断：有服务器就走接口；没有服务器但有 `codes.json` 就查码表；两者都没有就是预览环境，输入 `DEMO` 可以体验。
明文兑换码在 `codes/*.csv`（已被 git 忽略），用来上传到店铺；`public/tests/<id>/codes.json` 里只有哈希，可以提交。

## 部署

### 方式 A：纯静态（最省事，推荐起步）

1. `npm run codes:static -- jiucai 500 --prefix JC`，生成兑换码和码表；
2. 把整个 `public/` 目录交给任意静态托管即可，访问 `https://你的域名/jiucai/`：
   - 香港服务器上的 nginx / 宝塔：网站根目录指向 `public/`；
   - 其他静态托管也都可以。
3. 以后补码：再跑一次第 1 步，重新上传 `public/tests/jiucai/codes.json`。

### 方式 B：香港服务器 + Node 服务（要设备限制和数据统计时）

完整步骤见 [`docs/FRIEND-SOP.md`](docs/FRIEND-SOP.md) 的 B 节。

### 注意

- 面向大陆用户，不要用 Cloudflare 的 `*.pages.dev`：它在大陆多地打不开，原因见 [`docs/LAUNCH-CN.md`](docs/LAUNCH-CN.md)。
- 静态码表要用 HTTPS 访问才能校验，浏览器只在 HTTPS 下提供哈希计算功能。

### 线上预览

运行 `npm run build:preview -- jiucai --codes 9999,8888,6666,1688`，把 `out/preview/` 当静态网站发布即可（加 `--mode report` 可以切换付费方式）。`--codes` 里的测试码只写进预览包，不会进仓库，正式部署不受影响；不带 `--codes` 时输入 `DEMO` 体验。

## 出一套新测试（资产化的关键）

1. 复制 `public/tests/jiucai/` 为 `public/tests/<新id>/`，改 `config.js` 的内容。
2. 复制 `public/jiucai/index.html` 为 `public/<新id>/index.html`，把 `data-test` 改成新 id，再改标题。
3. 在 `public/index.html` 加一张卡片。
4. 运行 `npm run check`，再用 `npm run preview` 在手机宽度下走一遍。
5. 运行 `npm run notes -- <新id>`，生成这一套的笔记和商品素材。
6. 在服务器上用新前缀生成兑换码，上架新商品。

题量、选项数、维度数、段位数都可以改，引擎按配置自适应。人格数量 = 2 的维度数次方，每一种都要写全。

## 已知取舍

- 报告内容在前端，懂开发者工具的人可以绕过付费墙。0.99 元的产品不值得为此加服务端渲染。真要防的话，可以把 `types` 挪到服务端，由接口返回。
- 解锁状态存在本机浏览器里。服务器模式下每个码默认可在 3 台设备上用；静态码表模式不限次数。

## 和 Claude 协作的方式

把这个仓库交给 Claude（Claude Code），下面这些事可以直接让它做：

- **每周复盘**：把 `npm run admin -- stats` 的输出和小红书后台的数据截图发给它，它会定位漏斗卡在哪一步，并直接改文案、改题目、重新生成素材。
- **批量出笔记**：说「再来 10 个钩子」或「按年终奖 / 春节做一批借势笔记」，它会改配置、跑 `npm run notes`，再把素材交给你。
- **出新测试**：说「做一套粤语段位」，它会写配置，跑校验和分布模拟，截图验收，再生成笔记和商品素材。
- **合规审查**：发布前把笔记文案发给它过一遍；遇到平台规则变化，让它查证后调整高危词表和文案。
- **排障**：伙伴遇到报错或客服问题，截图发过来，它会给出命令或改代码。
