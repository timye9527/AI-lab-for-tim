# 成果中台

所有项目的交付成果登记在一个私有页面里。三个作用：登记成果、按主线给项目定档（每周三推三降）、检查有没有存进 GitHub。

- **页面（私有，只有自己能打开）**：https://claude.ai/artifact/HREAi1nCbVZNNFjuwFZiEc
- **页面源码**：`hub/index.html`
- **数据**：存在页面自带的数据集 `items` 里（只有本人可写），`hub/items.json` 是备份

## 收录规则

| 收 | 不收 |
|---|---|
| 能打开的页面、看板、网站 | 只做了搜索、资料整理，没有落成文件的对话 |
| 成型的研究报告、案例库 | 中间过程、草稿片段、调试记录 |
| 能用的产品、工具、游戏 | 空仓库、没开工的会话 |
| 可直接发布的内容素材、出图模板 | 已经并入其他成果的旧版本 |
| 视频、短片、PPT 讲稿 | |

## 五种类型（`cat` 字段）

| cat | 名称 | 放什么 |
|---|---|---|
| `invest` | 投研系统 | 持续更新的看板和投研工具 |
| `report` | 研究报告 | 一次成型的报告和案例 |
| `product` | 产品与工具 | 能用、能卖、能玩的东西 |
| `content` | 内容运营 | 账号、周报、笔记素材 |
| `media` | 影像与演示 | 短片、视频流程、PPT |

新增类型：改 `hub/index.html` 顶部的 `CATS`，然后重新发布到同一个网址。

## 定位和主线

判断一切项目的出发点：**交易是热爱，内容是优势，运营是职业，金融是长期赛道。** 交汇点是用内容把交易和金融的判断变成作品和收入，再用运营能力把它发出去。

| track | 主线 | 放什么 |
|---|---|---|
| `交易` | 交易与市场 | 交易本身和投研系统，保持盘感（SOXL 雷达、ETF 温度计、投研中枢） |
| `金融内容` | 金融内容 | 把金融判断做成视频、文章，直接变现（视频管线、投资账号文章） |
| `个人品牌` | 个人品牌 | 以 Tim 名义的作品、账号、演讲、音乐（短片、小红书、工作坊） |
| `运营与其他` | 运营与其他 | 职业相关和兴趣项目，不占主要精力（俱乐部系统、韭菜测试） |

## 优先级（priority）

| priority | 含义 |
|---|---|
| `重点` | 本阶段前三，投主要精力。全中台同时最多 3 个 |
| `推进` | 继续往前做，按节奏投入 |
| `维持` | 自动跑或按需做，不加投入 |
| `降级` | 前置条件没满足（比如要先有粉丝）或离主线远，只修必须修的 |
| `封存` | 做完存档，或旧版本已停 |

判断时看三件事：离「交易 × 金融内容」的交汇点有多近；有没有现成的变现路径、需不需要先满足前置变量；要持续投入多少时间、换来的是不是复利。暂停的项目把 `status` 设为 `暂停`。

## 成果形态（form）和职业相关（career）

页面侧栏除了按主线看，还能按成果形态跨主线看：

| form | 放什么 |
|---|---|
| `工具` | 每天在用的交易和看盘工具（ETF 温度计、SOXL 雷达） |
| `研究` | 投研系统、研究报告和案例 |
| `视频` | 财经视频管线和各期视频 |
| `作品` | 短片、音乐、演讲这些以 Tim 名义的作品 |
| `运营` | 账号、竞品周报、频道复盘 |
| `产品` | 做成产品形态、能给别人用的东西 |
| `方法` | 跨项目复用的技能和流程 |

`career: true` 表示和运营本职相关（账号运营、竞品周报、频道复盘、产品商业化、社群运营），页面上有「职业相关」入口集中看。

收藏和备注存在数据集 `data/users/<本人 id>/prefs`，每人一份，换设备也在。

## 项目性质（kind）和系统化

| kind | 含义 |
|---|---|
| `系统` | 长期运行、越用越值钱 |
| `跑流程` | 用单次项目验证一条流程。`runs` 记做了几次，**到第 3 次就要推动它系统化** |
| `一次性` | 做完即止 |
| `过程量` | 某个系统的一环或旧版本，用 `parent` 挂到所属系统下面，不单独占顶层 |

同一条管线的新旧版本不算重复建设：以最新版本为准，旧版本标 `过程量` + `封存` + `暂停`，挂在系统下面。

## 在别处推进的项目和 Codex 收件箱

- 主要在 Codex 等别的工具里推进的项目（目前是 SOXL 交易雷达、小红书个人号），填 `elsewhere: "Codex"`。中台只记录，不进三推三降、系统化和资产化提醒。
- Codex 那边的成果由 Codex 按 `hub/CODEX-PROMPT.md` 整理，交到 `hub/inbox/codex-YYYY-MM-DD.json`（分支 `codex/hub-inbox-*`）。周检时读进来、合并到数据集，合并完把文件移到 `hub/inbox/done/`。
- ETF 温度计网站的商业化、ETF 文章变现是自然会做的事，不单列项目，也不提醒。

## 资产化检查

目标：哪怕会话和容器都没了，也能从 GitHub 复现。

| asset | 含义 |
|---|---|
| `已入库` | 在仓库默认分支，有 README 说明怎么复现 |
| `在分支` | 推上了 GitHub，但还在 `claude/*` 等工作分支，没进默认分支 |
| `部分缺失` | 主体在，但成品、素材或最新版本不在（含按设计不进公开仓库的肖像、本人声音、成片） |
| `未入库` | 只在已发布页面或本机，GitHub 上没有 |

`assetNote` 写清在哪个仓库、哪个分支、缺什么。检查方法：`git ls-remote --symref <仓库> HEAD` 看默认分支，`git rev-list --count origin/main..origin/<分支>` 看分支领先多少提交。

发现缺口只提醒，不擅自合并：在周检结论里列出来，等 Tim 说补哪几项，再去合并分支、补 README、另存素材。

## 每周周检

每周一自动跑一次（Routine「成果中台周检」），也可以随时让 Claude 手动跑：

1. 盘点上次周检之后的新会话、新仓库提交、新发布页面，以及 `hub/inbox/` 里 Codex 交回的清单（含 `codex/hub-inbox-*` 分支）。新成果加条目，能挂到已有系统下面的就填 `parent`；旧成果更新日期和简介。
2. 重新定档：`track`、`priority`、`kind`、`runs`。重点最多 3 个；跑流程到第 3 次的列进系统化提醒；停更或条件变了的改档。
3. 逐项检查 `asset`。
4. 写周检结论到 `meta/review`：

```
{
  "date": "YYYY-MM-DD",
  "summary": "两三句话",
  "focus":  [{"id": "条目 id", "title": "重点推进", "why": "为什么", "next": "下一步"}],   // 正好 3 条，按先后排
  "drop":   [{"id": "条目 id", "title": "考虑降级", "why": "为什么"}],                    // 正好 3 条
  "actions":[{"kind": "拍板 | 补齐 | 保持", "title": "...", "text": "..."}]             // 最多 4 条
}
```

5. 同步 `hub/items.json` 和 `hub/review.json` 并提交。

## 登记一条新成果（给 AI 助手）

项目交付后（有页面、报告、产品、素材、视频或 PPT 落地），往数据集写一条：

```
ArtifactData set
  url:        https://claude.ai/artifact/HREAi1nCbVZNNFjuwFZiEc
  collection: items
  doc_id:     英文短名，如 jiucai-test
  data: {
    "title":   "标题",
    "cat":     "invest | report | product | content | media",
    "status":  "运行中 | 已上线 | 已交付 | 待完善 | 暂停",
    "date":    "YYYY-MM-DD（交付或最近更新日期）",
    "summary": "一两句话，说清是什么、核心产出",
    "tags":    ["最多三个"],
    "source":  "仓库名 或 仓库 · 分支",
    "links":   [{"label": "打开页面", "url": "https://..."}],
    "track":    "交易 | 金融内容 | 个人品牌 | 运营与其他",
    "priority": "重点 | 推进 | 维持 | 降级 | 封存",
    "kind":     "系统 | 跑流程 | 一次性 | 过程量",
    "form":     "工具 | 研究 | 视频 | 作品 | 运营 | 产品 | 方法",
    "career":   false,
    "parent":   "所属系统的 doc_id（可选）",
    "runs":     2,
    "why":      "一句话判断理由",
    "next":     "下一步（重点和推进填）",
    "asset":    "已入库 | 在分支 | 部分缺失 | 未入库",
    "assetNote":"在哪、缺什么",
    "reviewed": "YYYY-MM-DD"
  }
```

- 同一个项目更新了，就更新原条目（先读出 `version` 再写），不要新开一条
- 写完后把同样内容补进 `hub/items.json`，一起提交
- 只做了检索、没有交付物的会话不登记
