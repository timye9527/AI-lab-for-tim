# 给 Codex 的提示词：成果中台对齐

把下面整段复制给 Codex。它会按同一套规则，整理 Codex 那边的项目，交回一份能直接并进成果中台的清单。

---

你在帮 Tim（GitHub 账号 timye9527）整理他在 Codex 这边做过的项目成果，并按他的长期主线给每个项目定档。Claude 那边已经有一个「成果中台」，管着 Claude 会话里做的项目；你负责 Codex 这边，最后交一份同格式的清单，由 Claude 合并进中台。

## 一、Tim 的定位（所有判断的出发点）

- **交易是热爱**：交易本身让他保持对市场的敏感度。
- **内容是优势**：既有观点和表达的输出，也有互联网上的产品、片子、音乐，可以互相融合。
- **运营是职业**：账号、分发、商业化是他的本行。
- **金融是长期赛道**：他想长期在这里赚钱、创造价值的细分领域。

交汇点：用内容把交易和金融的判断变成作品和收入，再用运营能力发出去。

## 二、三条主线 + 一组其他（字段 `track`）

| track | 放什么 |
|---|---|
| `交易` | 交易本身和投研系统：SOXL 交易雷达、ETF 温度计、投研中枢 |
| `金融内容` | 把金融判断做成视频、文章：财经视频管线、爆款周报 |
| `个人品牌` | 以 Tim 名义的作品、账号、演讲、音乐：短片、小红书、工作坊 |
| `运营与其他` | 职业相关和兴趣项目，不占主要精力：俱乐部系统、韭菜测试、学习工具 |

## 三、Tim 已经拍板的决定（不要改回去）

- **SOXL 交易雷达**：最重要的资产之一，主要在 Codex 这边推进，Tim 会定期结合数据更新。你这边要把它整理清楚。
- **ETF 温度计**：网站要持续开发、打磨，以后会往商业化走。ETF 文章变现是自然会做的事，不用单列成项目，也不用提醒。
- **小红书**：路径是个人品牌 → 商业化，但账号还没跑通；出图有一部分在 Codex 里做。按实际进度记录，不要夸大。
- **财经视频**：内容工厂（深度内容，比如投资人演讲改编）和存力研究所（聚焦某个行业）是两个不同方向，两条线都保留，不算重复建设。同一条线的旧版本以最新版为准，旧的停掉。
- **Finance 930 自频道周复盘**：暂停。
- **AI 实战工作坊**（PPT、工具包网站）：活动结束，搁置。
- **韭菜段位测试**：要先有小红书粉丝才能变现，降级。
- **EOE Club OS**：周期长，离主线远，降级。

## 四、你要做的事

1. **盘点 Codex 这边的项目**。包括但不限于：
   - `soxl-trading-radar`：main，以及所有 `codex/` 分支
   - `ai-workshop-toolkit`：默认分支 `codex/ai-workshop-toolkit`
   - 小红书出图相关的脚本和模板
   - 本机上的项目，比如 `~/finance-hits`、`~/finance930-ops`、`~/memory-desk`、`~/Documents/Codex/` 下的粤语闯关
   - 你记得的、或在本机 Codex 项目目录里找得到的其他项目

   只收有交付物的：页面、系统、报告、素材、视频、PPT。只做了检索、或者没开工的不收。
2. **逐个定档**。按第五节的字段，给每个项目写 `track`、`priority`、`kind`、`why`、`next`。第三节已经定了的，照着写。
3. **资产化检查**。逐个确认能不能从 GitHub 复现：
   - 用 `git ls-remote --symref <仓库> HEAD` 看默认分支
   - 用 `git rev-list --count origin/<默认分支>..origin/<分支>` 看工作分支领先多少提交
   - 看成品和素材是否在仓库里，以及有没有只放在本机、没推上去的东西（比如 `~/memory-desk`）

   **只记录，不要自己合并分支、不要删分支、不要推送到别人的仓库**。缺口写进 `assetNote`，Tim 决定先补哪几个。
4. **顺手优化 Codex 这边**。对 Tim 定为重点或推进的项目，可以补 README 里缺的复现步骤、把明显该提交却没提交的源码提交到各自的工作分支。改动范围要小，每处改动都写进清单的 `codexChanges`。
5. **交付**。把清单写成一个 JSON 文件，提交到仓库 `timye9527/AI-lab-for-tim` 的 `hub/inbox/codex-YYYY-MM-DD.json`，推到新分支 `codex/hub-inbox-YYYY-MM-DD`。推不上去就把 JSON 原文贴给 Tim。

## 五、字段规则

| 字段 | 取值 |
|---|---|
| `priority` | `重点`（本阶段前三，全中台最多 3 个）、`推进`、`维持`、`降级`、`封存` |
| `kind` | `系统`（长期运行）、`跑流程`（用单次项目验证流程，`runs` 记次数，到第 3 次要系统化）、`一次性`、`过程量`（某个系统的一环或旧版本，用 `parent` 挂到所属系统下） |
| `status` | `运行中`、`已上线`、`已交付`、`待完善`、`暂停` |
| `asset` | `已入库`（在默认分支，有 README，能复现）、`在分支`（推上去了，但在工作分支）、`部分缺失`（缺成品、素材或最新版本）、`未入库`（只在本机或页面上） |
| `form` | `工具`、`研究`、`视频`、`作品`、`运营`、`产品`、`方法` |
| `career` | 和 Tim 运营本职相关（账号运营、竞品周报、频道复盘、产品商业化、社群运营）填 `true` |
| `elsewhere` | Tim 主要在 Codex 推进的项目填 `"Codex"`，中台就只记录、不单独提醒 |

## 六、交付格式

```json
{
  "from": "codex",
  "date": "YYYY-MM-DD",
  "items": {
    "soxl-radar": {
      "title": "SOXL 交易雷达",
      "cat": "invest",
      "track": "交易",
      "priority": "推进",
      "kind": "系统",
      "form": "工具",
      "career": false,
      "status": "运行中",
      "date": "最近一次有实质更新的日期",
      "summary": "一两句话：是什么、核心产出、现在到哪一步",
      "why": "一句话判断理由，贴着 Tim 的定位写",
      "next": "下一步（重点和推进填）",
      "asset": "已入库",
      "assetNote": "在哪个仓库、哪个分支、缺什么",
      "elsewhere": "Codex",
      "source": "仓库 · 分支",
      "links": [{"label": "仓库", "url": "https://github.com/timye9527/soxl-trading-radar"}],
      "tags": ["最多三个"],
      "codexChanges": ["这次你改了什么，没改就留空数组"]
    }
  },
  "notes": "中台里已有、但你认为判断不对的地方，或者 Tim 需要拍板的事，最多 5 条"
}
```

- `doc_id` 用英文短名。中台里已有的项目沿用这些 id：`soxl-radar`、`etf-temperature`、`invest-desk`、`ai-workshop-toolkit`、`eoe-ai-workshop`、`xhs-account`、`xhs-yanni`、`canto-pop-quest`、`finance-hits`、`finance930-ops`。
- `cat` 取 `invest`、`report`、`product`、`content`、`media`。
- 文案用中文，写给 Tim 看，平实直接，不要夸大进度。数字和状态要能在仓库或本机找到依据，找不到就写「未核实」。

最后用几句话告诉 Tim：盘点了多少个项目、各自什么档、资产缺口里最该先补的三个、你这次在 Codex 这边改了什么。
