# 财经浩谈 · 节目拆解与优化方案

> 写于 2026 年 10 月。**说明：** 云端环境连不上 YouTube，原视频（`youtube.com/watch?v=5jamBHrMd-8`）本身没有看到。下面的拆解来自三方面：
> 一张节目截图、公开搜索结果、以及按截图复刻出来的制作流水线（`video/`）。标「推测」的地方，用 `npm run video:teardown` 在能上 YouTube 的电脑上跑一遍原片就能核实。

## 一句话结论

**手绘插画 + 卡通主持人这个形式适合宏观内容，不用推翻。** 不够爆，问题大概率出在三处：**包装**（标题、封面）、**节奏**（一张图停 10 秒，上完色就不动了）、**信任**（看不出是谁在讲）。
建议保留手绘风，改成「插画讲比喻 + 数据卡讲数字」混剪，每 3～6 秒有新信息；开头 15 秒先抛数字或冲突；每集再剪 2 条 Shorts 引流。

整套流程已经做成脚本，一篇稿子进去，长视频、Shorts、封面、字幕、上传文案一起出来，见 [`video/README.md`](../video/README.md)。

## 1. 现在的节目是什么样

### 已知信息

- 节目名「財經浩談」，YouTube 视频描述里带 `#財經浩談` 标签，有一集讲 AI 算力融资和循环融资风险，带章节时间轴。
- 内容来源：分析师李浩然。他在信报有专栏「經緯浩談」（同时发在 Substack），近期写的主题有 AI 泡沫、CoreWeave 债券、美债息压科技股。节目和专栏的选题高度重合，推测是**专栏稿改编成视频**。
- 截图左上角是「方德智投 FORTHRIGHT」的标志。方德是香港的持牌券商，推过 AI 投资终端。所以这是**券商品牌的内容节目**，合规要求会比个人频道严。

### 截图拆解

| 元素 | 现在的做法 | 判断 |
|---|---|---|
| 主画面 | 一张手绘风插画，圆角画框，先出线稿再上色，有一只拿记号笔的手在画 | 形式好，有「看着它画出来」的期待感 |
| 主持人 | 左下角 3D 卡通人物，假对口型 | 品牌统一、不用真人出镜；但存在感弱，看不出是谁 |
| 字幕 | 白字粗黑描边，压在画框下沿 | 清楚，手机上能看 |
| 信息条 | 右上「稿件日期」，底部常驻「风险及免责声明」 | 合规必需；日期说明内容有时效 |
| 节奏 | 约 10 秒一幅画（你朋友描述的） | **最可能的流失点** |

### 推测的制作流程

分析师写稿 → AI 改写成口播稿 → AI 粤语配音 → AI 出插画（带文字和 logo）→ 手绘动画工具做「画出来 + 上色」→ 卡通形象对口型 → 加字幕、免责条 → 上传。

截图里能看到这个流程的几个痕迹：插画里的「57億歐元」「CoreWeave」是 AI 直接画进图里的，CoreWeave 的 logo 被手挡住一半；一张图里同时塞了 ASML 和 CoreWeave 两个故事加两个年份。

## 2. 这个形式适不适合宏观内容

### 有没有对标

| 对标 | 形式 | 能说明什么 |
|---|---|---|
| [Ray Dalio《How the Economic Machine Works》](https://www.bridgewater.com/research-library/how-the-economic-machine-works) | 30 分钟动画，讲信贷周期和去杠杆 | 宏观内容用简笔动画讲，是被验证过的。不过它的看点在讲清机制，不在追新闻 |
| [WhiteBoard Finance](https://creatordb.app/creatorstats/whiteboardfinance/) | 手绘白板讲理财投资，100 万+订阅 | 手绘白板在财经类能做到百万订阅；第三方数据称它的互动率远高于同类中位数 |
| [Primate Economics](https://outlierkit.com/channel/primateeconomics) | 动画讲宏观，比如「用香蕉讲通胀」 | 「一个好比喻」就是一集的卖点 |
| [Economics Explained](https://outlierkit.com/channel/economicsexplained) | 素材 + 动画讲宏观，约 290 万订阅 | 宏观解说有大盘子 |

**粤语这边**：搜不到以手绘动画讲宏观的粤语频道（搜不到不等于没有，要在 YouTube 上再人工搜一遍）。粤语财经大多是真人访谈、直播、新闻读稿，**「手绘 + 粤语 + 宏观」可能是空位**。

### 适合讲什么，不适合讲什么

| 适合（插画） | 不适合（插画），要换数据卡 |
|---|---|
| 机制：循环融资、利率怎么传导到楼价 | 精确数字：自由现金流 1,910 亿、市盈率 41 倍 |
| 因果链：A 发生 → B 受压 → C 爆煲 | 走势：过去 10 年债息 |
| 历史类比：1999 电讯泡沫 vs 今天 | 多个数值对比 |
| 情绪和立场：乌云压在服务器上 | 需要出处的数据（插画里放出处很别扭） |

**原因**：插画的强项是比喻，让抽象概念「看得见」；弱项是数字。AI 画的数字和中文常出错，改一个字要重新出图；公司 logo 还有商标风险。

### 卡通主持人

- **好处**：形象统一、可以日更、不用真人出镜，合规上也省事。
- **问题**：财经内容卖的是「信任」。一个没名字、没来历的卡通人物，观众不知道该不该信他。对口型粗糙时还会有廉价感。
- **建议**：
  1. 给形象一个固定名字和人设（比如「浩哥」），固定开场白和口头禅，让观众记得住。
  2. 把分析师的身份亮出来（经本人和公司同意）：片头一行「主笔：李浩然 · 信报《經緯浩談》专栏作者」。专栏作者的身份，是这个节目最值钱、但现在没用上的资产。
  3. 形象放在画面一角，不要挡内容；动作可以简单，但嘴型要跟得上声音（流水线已经按音量自动对嘴）。

## 3. 为什么不够爆：诊断清单

没看到后台数据，下面是按经验排的可能原因。**拿 YouTube 后台的数据逐条对一下，就知道是哪一条。**

| 环节 | 看哪个数据 | 可能的问题 | 怎么改 |
|---|---|---|---|
| 有没有人点 | 曝光点击率（CTR） | 封面信息太多、字太小；标题是书面语专栏题，没有关键词 | 封面：两行大字（每行 ≤5 字）+ 一个大数字 + 插画；标题：公司名 / 事件 / 数字放最前 |
| 点进来留不留 | 30 秒留存 | 开头先介绍节目、先铺背景 | 第一句就是数字、冲突或问题（「五千億美元。呢筆錢唔係輝達賺返嚟……」） |
| 中段塌不塌 | 留存曲线的下坡位置 | 一张图停 10 秒，上完色就静止 | 插画上做镜头推移，跟着口播推到不同位置；数字换数据卡；每 3～6 秒有新东西 |
| 看完有没有反应 | 评论数、订阅转化 | 结尾没有互动问题 | 结尾抛一个观众能站队的问题 |
| 有没有新流量 | 流量来源里 Shorts、搜索占比 | 只发长视频 | 每集剪 2 条 Shorts；上传 SRT 字幕和章节，吃搜索流量 |
| 时效 | 发布时间 vs 新闻时间 | 「稿件日期」说明是追新闻的内容，晚一两天热度就过了 | 专栏见报当天出片，流水线一小时内能出预览 |

截图本身能看到的具体问题：

1. **一图两事**：ASML 的 57 亿欧元订单和 CoreWeave 的乌云塞在同一张图里，手机上看不过来。一张图只讲一件事。
2. **字在图里**：数字、公司名是 AI 画进去的，错了不好改，logo 还被手挡住。文字应该由程序叠上去。
3. **节目品牌弱**：「財經浩談」四个字只出现在记号笔上，券商 logo 占了左上角。节目名应该是观众记住的东西。
4. **免责条常驻**：合规上需要的话就保留，可以做得更细、更淡，**改之前一定先问公司合规**，不要自己删。

## 4. 优化方案（按优先级）

| 优先级 | 做什么 | 成本 | 流水线里对应的功能 |
|---|---|---|---|
| P0 | 封面和标题重做，用 YouTube 的「测试与比较」功能 A/B 测封面 | 低 | `thumb` 自动出封面；`youtube.txt` 提醒标题长度 |
| P0 | 开头 15 秒改成「数字 / 冲突 / 问题」 | 低 | AI 改稿规则第 3 条；`hook` 场景 |
| P1 | 插画 + 数据卡混剪，插画上加镜头推移，文字由程序叠加 | 中 | `sketch` 场景（线稿 → 上色 → 镜头）+ `number` / `bars` / `flow` 等 |
| P1 | 每集 2 条 Shorts | 低 | `short: 'a'` 标记，自动出竖屏 |
| P1 | 上传 SRT 字幕、写章节 | 低 | `long.srt`、`youtube.txt` 自动生成 |
| P2 | 主持人人设、分析师身份露出 | 中（要公司同意） | `host` 形象；`title` / `kicker` 加署名 |
| P2 | 固定更新节奏，按主题建播放列表（AI 泡沫、美债、港股） | 低 | — |
| P3 | 真对口型 | 中 | 见 `video/README.md`「后续可以升级的地方」 |

**每周复盘**：后台数据截图 + 当周一条片的 `npm run video:teardown` 报告，一起交给 Claude 看，定位卡在点击、开头还是中段，再改下一集。

## 5. 流水线已经跑通的部分

用一篇示范稿（AI 根据公开新闻编写，**只用来跑流程，不代表分析师观点**，数字都标了「发布前核对」）在云端完整跑了一遍：

- 18 个场景、约 3 分钟的长视频，纸面手绘主题：插画线稿 → 上色 → 镜头推移，数据卡、资金流向图、对比卡，主持人按音量对嘴，常驻免责条和稿件日期。
- 2 条竖屏 Shorts、插画封面、SRT 字幕、带章节时间码的上传文案。
- 音频链路用替代音源测过：配音按场景对齐，背景音乐在说话时自动压低，整体响度 -14 LUFS。
- 用拆解工具检查自己的片：第一版平均 12 秒才换一次画面，太慢；据此给渲染脚本加了「场景太长」提醒，也改了 AI 改稿规则。

**没有跑的部分**（云端环境的网络限制）：

- 真实粤语配音：云端连不上 edge-tts 的语音服务，示范片是无声的，时长按字数估算。在自己电脑上装好 edge-tts 就会自动配音。
- AI 改稿：没有配置 API 密钥，`video:draft` 只做了代码检查，没有真实调用。
- 原视频拆解：连不上 YouTube。
