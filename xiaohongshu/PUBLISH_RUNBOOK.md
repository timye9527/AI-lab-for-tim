# 存草稿 / 发布流程（由能操作已登录浏览器的执行方完成，如 Codex）

**当前模式：只存草稿。** 执行方把已批准版本填好并存为草稿；最终“发布”由委托方本人在手机端点击。执行方不点“发布”。

## 准备

1. 交接文件夹完整（含 `review/E01-v4/upload/` 6 张图）。
2. 运行 `python3 tools/prepublish.py E01-v4`：打印标题、正文、Tag、图片顺序与校验值；版本未批准、已存过草稿、已发布或缺图时会停止，不要绕过。

## 存草稿

1. 已登录的浏览器打开 https://creator.xiaohongshu.com → 发布笔记 → 上传图文。
2. 按 01→06 上传图片，核对缩略顺序。
3. 标题、正文从 `review/E01-v4/post.md` 原样粘贴；话题逐个添加：读书、阅读方法、表达能力、罗翔、自我提升。
4. 与 prepublish 输出逐项核对后点“暂存/存草稿”，只存一次；到草稿箱确认存在。
5. `progress.json` 的 `xhs_drafts` 记录 `{"id","saved_at","where","verified"}`。
6. 若页面报错或不确定是否存上：先去草稿箱/笔记管理查，确认没有再重试。

## 发布之后

- 委托方手机端发布后，执行方在“笔记管理”找到该篇，把链接、时间、状态写进 `progress.json` 的 `published_posts` 与 `review/metrics.json`，该日为 Day1。
- 24小时、7天读取曝光、阅读、点赞、收藏、评论、主页访问、单篇新增关注，读不到写 null；账号总粉丝差不能冒充单篇。

## 不能做

- 不输入、保存或导出密码/Cookie；登录与身份验证由委托方完成。
- 不刷粉、不群发、不删旧帖、不改账号资料。
- 未获委托方针对具体版本的“直接发”，不点发布。
