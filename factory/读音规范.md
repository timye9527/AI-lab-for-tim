# 读音规范 · 配音不能在基础上出错

配音模型自己决定读音时，最常错的就是下面这些。实际踩过的坑逐条记在 [`错误档案.md`](错误档案.md)。我们的做法是**读音由我们决定，模型只负责发声**：`video/pron.py` 先把口播稿逐字转成拼音，再生成一份附加词典，让模型逐字照读。

## 容易出错的地方和处理方式

| 类型 | 典型错误 | 处理 |
|---|---|---|
| 多音字（按词） | 行长读 xíng、调研读 tiáo、重仓读 chóng、长期读 zhǎng | pypinyin 按词取音，财经常用词写进 `pron.txt` 覆盖 |
| 多音字（按语境） | 「就**得**回答」应读 děi、「传**得**最广」应读 de；「去**量** AI」应读 liáng；「**冲**着」应读 chòng；「付**了**账」应读 le；「稳固**地**」应读 de | 词典按词取音也会错。高风险字读成少见音时列入读音表「重点审」；少见音才对的搭配用语境规则抓（见下节）；审过的写进 `pron.txt` |
| 模型弱音节 | 「你总**得**知道」：指令写 děi，模型实际读成 dé | 模型本身发不出 děi（声学实测）。`pron.py` 的 `WEAK` 登记，稿子里出现直接报错，必须改写（总得 → 必须 / 一定要，就得 → 就要） |
| 「一」「不」变调 | 一样读 yī、一间读 yī、不是读 bù | 程序按规则变调：一在四声前读 yí，在一二三声前读 yì，在数字、序数、句尾读 yī，「看一看」读轻声；不在四声前读 bú |
| 三声连读 | — | 不写进拼音，交给模型（模型训练时就是这么标的） |
| 轻声 | 的、了、着、子 | 用 5 标轻声，「地方」等常用词写进覆盖表 |
| 数字 | 10% 读成「十 percent」、2025 读成「两千零二十五」 | 程序先转汉字：年份逐位读（一九九三年）、百分比读「百分之十」、区间读「六十到七十」、千万亿前的二读「两」、「中国制造2025」逐位读 |
| 数字的含义（005 期） | 「924」（9 月 24 日的简称）读成「九百二十四」 | **先判断这个数是什么**：数值、数量按数值读（3794 点、4418 亿）；代号、日期简称、编号逐位读（924、618、315、911）。纯数字的读法写在 `read.txt`（「924 => 九二四」），只在后面没有单位时生效，「924亿」仍按数值读。没有单位的三位以上整数，读音表单列「数字读法待确认」，质检记一项提醒，确认后写进 `read.txt` 才算干净 |
| 英文缩写 | AI 读成一个音「爱」、单个大写字母被当成音素符号 | 每个字母的读法都用识别模型验证过（`letters.txt`）：多数用中文音节读字母（A 读 éi、I 读 āi，播音里读缩写的方式），H、J、Q、U 交给英文引擎；L、Z 读不准，稿子里禁用。新缩写先跑 `npm run video:letters` |
| 英文单词 | 中文模型乱读 | 交给 espeak 按美式英语读；能用中文说的尽量用中文（《证券分析》而不是 Security Analysis） |
| 人名、机构 | 李录读成李路的声调、格雷厄姆的「厄」 | 人物池里的人名、机构名全部写进 `pron.txt` |
| 符号 | 「·」「《》」被读出来或吞字 | 程序直接去掉 |
| 儿化 | 模型不稳 | 口播稿不写儿化 |

## 多音字语境规则

多音字不能只看字，要看它在这句话里是什么意思。审读音表时按这个顺序判断：

1. **读出整句**，想清楚这个字在句子里做什么（动词？补语？量词？虚词？）。
2. **对照下表**，按意思定读音。
3. 拿不准就查《现代汉语词典》。
4. 定了读音还不够，要确认**模型发得出这个音**：弱音节（目前有 děi）一律改写。

> 回听质检对多音字是盲的：识别模型听到 děi 和 dé 都写「得」。多音字读得对不对，只能靠读音表、弱音节规则和人耳。

| 字 | 按意思判断 | 例子 |
|---|---|---|
| 得 | 必须、需要 → děi（**本模型发不出，必须改写**）；动词后面接补语 → de（轻声）；得到、获得 → dé | 就得、还得、总得 → 改成就要、还要、必须 / 传得最广、看得懂、值得 / 赢得、不得不 |
| 了 | 句末、动词后表示完成 → le；「能不能」的意思 → liǎo | 付了账、缩水了 / 到不了、受不了、了解 |
| 着 | 动作持续 → zhe；着急 → zháo；着眼、着手 → zhuó | 连着、冲着 / 着急 / 着眼于价值 |
| 量 | 动词「测量」→ liáng；名词「数量」→ liàng | 去量 AI、量完 / 大量、数量 |
| 还 | 仍然 → hái；归还 → huán | 还有、还是 / 还钱、还债、偿还 |
| 为 | 为了、替 → wèi；是、成为、作为 → wéi | 为你服务、在为代价买单 / 本视频为…、认为、作为 |
| 地 | 结构助词（副词后面）→ de；土地、地方 → dì | 稳固地进入 / 地区、地方 |
| 长 | 长短、长期 → cháng；增长、董事长 → zhǎng | 长期、长线 / 增长、行长 |
| 行 | 行走、行动 → xíng；银行、行业 → háng | 行动、发行 / 银行、行情 |
| 重 | 重要、重仓 → zhòng；重新、重复 → chóng | 重仓 / 重组、重新 |
| 调 | 调研、强调 → diào；调整、调仓 → tiáo | 调研 / 调仓、调控 |
| 只 | 仅仅 → zhǐ；量词 → zhī | 只有 / 几只股票 |
| 应 | 应该 → yīng；应对、应用、供应 → yìng | 应该 / 应对、供应 |
| 冲 | 冲击 → chōng；对着、冲着 → chòng | 冲击 / 冲着格雷厄姆 |
| 中 | 中国、中间 → zhōng；中奖、打中 → zhòng | 中国 / 中标 |

程序做两件事帮忙：高风险字读成**少见音**时列入「重点审」（读成常见音的不列，免得噪音太多）；「还钱」「几只股票」「中奖」这类**少见音才对**的搭配，用语境规则（`pron.py` 的 `CONTEXT`）专门抓，命中但读得不对时标出「按语境应读 X」。

## 节奏：专有名词被读断（005 期）

模型只看到一串音节，不知道哪几个字是一个词。四字专名会被读成「短长短长」：实测「恒生科技」每个字占 恒 0.12 / 生 0.30 / 科 0.12 / 技 0.36 秒，「科」被挤短、「技」被拖长，听起来像「恒生科，技」。

- **同一段文字，这个模型每次合成的节奏都一样**（实测 3 次完全相同），重读改不了，只能换说法。
- **附加词典怎么切不影响节奏**：曾怀疑是按 10 个字切词典条目、切在词中间造成的，对照实验（按 10 字切 vs 按词切）结果完全一样，排除。
- **改法**：用带中心词的全称或通行简称，让拖长落在名词短语的最后一个字。实测「恒生科技指数」里「技」从 0.36 降到 0.24，「恒科指数」名字内部没有拖长，只有末字「数」拖长（自然）。
- **怎么查**：觉得某个词读得断，用 `npm run video:rhythm -- "说法一" "说法二"` 对比每个字占多长，标「↑拖长」的是句中被拉长的字（逗号前、句尾的拖长是正常的）。

## 偶发故障：重复音节、串音、吞字

模型合成有随机性，同一句话偶尔会冒出重复音节（「套利」读成「套号利」）、串音或吞字，读音表查不出来。现在每句合成后都自动回听：

- SenseVoice 和 Paraformer 两个识别模型各转写一次，转成不带声调的拼音，和稿子逐音节比对；听到的字只要有一个读音对得上就算对，所以同音字、多音字不误报。
- 不对就重读：前 3 次原样，再 2 次微调语速，最后 3 次拆成短句合成；取错得最少的一次。噪声强度从默认 1.0 降到 0.667，偶发故障更少。
- 8 次都不过，说明模型在这个词组上有硬伤，必须改写稿子（001 期改了 3 句），不允许带病出片。

## 每期必做

1. 写稿时照常写汉字、数字和英文缩写，不用管读音。
2. `npm run video -- <期目录> --no-video`：生成配音、读音表和质检报告，每句自动回听、不对就重读。
3. 打开 `episodes/<期>/读音表.md`：按上面的语境规则逐个判断「重点审」，再扫一遍逐句标注。读错的在 `video/pron.txt` 加词（带上前后一两个字，避免误伤别的句子）。
4. 回听只能发现多字、漏字、串音，**发现不了声调错误**，所以第 3 步不能省。审过确认没错的词也写进 `pron.txt`，下次就不用再审。
5. 新出现的人名、机构名、术语，第一次用就加进 `pron.txt`。
6. 读音表里「数字读法待确认」的每个数，按含义定读法后写进 `read.txt`；「数字读法」一节扫一眼，看有没有该逐位读却按数值读的。
7. 新出现的四字以上专名（指数名、机构名），先用 `npm run video:rhythm` 听节奏，被读断就换全称或通行简称。

## 为什么换掉了第一版的声音

第一版用的是 Kokoro 的中文男声，模型本身的中文带口音，听感「怪」，而且多音字靠它自己猜。现在用的是 Matcha 中英双语模型（标准普通话女声，中英混读），读音完全由我们控制。

对比测试用的是同一段「刁钻」文本（多音字、英文缩写、百分比、年份、人名混在一起）：

| 模型 | 字错率 | 主要问题 |
|---|---|---|
| Matcha 中英（现用） | 0.10 → 接入读音模块后整期 0.028 → 加回听重读后整期逐音节全部通过 | 16 kHz 采样，比广播级略闷 |
| 标贝 Matcha | 0.20 | 不读英文；「行长」读 xíng cháng |
| MeloTTS 中英 | 0.20 | 「李录在」读成「以路赛」 |
| Kokoro 男声（第一版） | — | 口音、读音不可控 |

## 再往上升级

- **想要男声或更有感染力的声音**：离线开源模型里目前没有又标准又是男声的好选择。最实际的两条路：
  1. 云端配音。这个环境能连上谷歌云语音合成（普通话和英语都有高质量男声），需要一个 API Key。
  2. 用这里导出的 `subs.srt` 在剪映里换付费音色重配，读音表照样拿来逐句核对。
- 无论换成什么声音，**读音表这一步都保留**：先定读音，再配音。
