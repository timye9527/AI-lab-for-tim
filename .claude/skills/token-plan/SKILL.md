# 省 token 规划

花钱的大头不是写，而是**每一步都要把整段对话重读一遍**。审计数据：81% 的费用花在重读和重建上下文上。
所以只有两件事最重要：**对话别拖长，旧对话别隔天续。**

同目录文件：`模板.md`，里面有任务卡、PROGRESS.md、一页规格书和新会话开场白的模板。

## 一、开干前：先出任务卡（新任务必做，1 分钟）

动手前不读大文件、不搜索、不写代码，先回给用户一张**任务卡**（≤15 行，格式见 `模板.md`），用户确认后再开始：

1. **这个对话只做什么、做到什么程度停。** 一句话说清"完成标准"。范围太大就拆成几段，每段一个对话。
2. **任务类型 → 阶段。** 探索类项目按 调研 → 一页规格书 → 计划 → v0 → v1.0 走，**本对话只做当前这一段**。执行类（改文案、渲染、修 bug）直接做。
3. **交付文件。** 每一段都要落成文件（`docs/research.md`、`docs/SPEC.md`、`docs/PLAN.md`、`PROGRESS.md`），后续对话只靠文件交接，不靠聊天记录。
4. **模型和思考强度。** 设计、架构、难 bug 用 high；按清单执行、改文案、渲染、批量处理用 medium。xhigh 只在卡住时临时用。和当前设置不一致时提醒用户切换。
5. **调研走子代理。** 要搜索 5 次以上、读长文档或看大量图片时，交给子代理，要求它"只带回一页结论 + 出处"，原始材料不进主对话。
6. **v0 范围。** 探索类项目先定"最小能跑通的一个核心场景"，其他都列进"不做"。
7. **止损线。** 写明：同一问题 3 轮没进展就停；本对话预计花费超过约 $15 就收口复盘。

用户说"直接干"或任务很小（一句话能做完的改动），就跳过任务卡，只用一行说明"本对话做 X，做完就收口"。

## 二、做的过程中

- **长输出先落文件。** 测试、渲染、构建、日志、爬取结果写进文件，只打印最后 20 行或摘要。
- **先定位再读。** 用 grep 找到位置，只读需要的片段；不要整篇读大文件。
- **同一个错两次就停。** 先说根因，再改；不要连续重试。
- **看图要省。** 一次最多看 4 张，先缩到 720p 以下。
- **该收口的信号**（出现任何一条就主动提醒用户）：
  - 当前阶段的交付文件已经写完；
  - 本对话已经调用了约 60 次工具，或者读过大量搜索结果、图片、长文档（上下文多半已过 20 万）；
  - 用户隔了一个小时以上才回来，而这个对话已经很长（缓存已经失效，再续就要整段重建）；
  - 话题换了，开始做和本对话目标无关的事。

## 三、收口：交接给下一个对话

收口时按顺序做：

1. 更新 `PROGRESS.md`（模板见 `模板.md`，≤40 行）：已完成、已定决策、下一步、卡点。
2. 提交并推送。
3. 给用户一句**新会话开场白**，让用户复制到新对话里：
   > 读 PROGRESS.md 和 docs/SPEC.md，从「下一步」第 1 条继续。本对话只做：<下一段的目标>。

**收口还是压缩？**
- 阶段做完，或者用户要离开一段时间 → **收口，开新对话**（最省）。
- 还在同一件事中间、只是对话变长了 → 提醒用户输入
  `/compact 保留：当前目标、已定决策、下一步；丢掉：调研原文、旧版本、试错输出`
- 用户问"上下文多大了" → 让用户输入 `/context` 看，Claude 自己看不到准确数字。

## 四、用户说"继续上次的"

- 先找 `PROGRESS.md`；有就按它的「下一步」继续，不要翻旧对话。
- 没有 `PROGRESS.md`：先花几分钟根据 git log 和现有文件补一份，让用户确认，再继续。
- 如果用户正在一个已经很长、隔了很久的旧对话里说"继续"：建议用户先让这个对话写好 `PROGRESS.md`，然后开新对话接着做。
