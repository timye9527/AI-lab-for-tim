# 模板

## 1. 任务卡（开干前回给用户，≤15 行）

```
【任务卡】
本对话目标：<一句话>　完成标准：<做到什么就停>
任务类型：探索 / 执行 / 调研 / 修改　当前阶段：<调研 / 规格 / 计划 / v0 / v1.0>
交付文件：<docs/xxx.md 或具体产物>
拆分：本对话做 <A>；之后新对话做 <B>、<C>
模型 / 强度：<Opus high 或 medium>（当前是 <x>，<需要 / 不用>切换）
调研：<不需要 / 交给子代理，只带回一页结论 + 出处>
v0 范围：<一个核心场景>；不做：<列出来>
止损：同一问题 3 轮没进展就停；超过约 $15 就收口
确认后开始？
```

## 2. PROGRESS.md（放在仓库根目录，≤40 行，每次收口都更新）

```markdown
# 进度（更新于 YYYY-MM-DD）

## 当前目标
<一句话>

## 已完成
- <事项>（提交 abc1234）

## 已定决策（不要再讨论）
- <决策 + 一句理由>

## 下一步（按顺序，每步可验证）
1. <步骤>：做完的标志是 <xxx>
2.

## 已知问题 / 卡点
- <问题>：已试过 <方案>，怀疑根因 <xxx>

## 新对话开场白
读 PROGRESS.md 和 docs/SPEC.md，从「下一步」第 1 条继续。本对话只做：<目标>。
```

## 3. 一页规格书 docs/SPEC.md（探索类项目第二段的交付物）

```markdown
# <项目名> 规格书 v0

- 给谁用：<具体人群>
- 解决什么问题：<一句话>
- 核心场景（最多 3 个）：
  1.
- v0 只做：<一个场景>
- 不做：<列出来，防止范围膨胀>
- 验收标准：<怎样算 v0 能用>
- 风险 / 未知：<需要先验证的点>
```

## 4. 调研子代理的指令

```
调研：<问题>。
要求：只返回一页结论（≤600 字）+ 出处列表；不要返回搜索原文。
重点回答：<2–4 个具体问题>。
```
