## 零、每次必查（重复犯过、或者代价最大的 15 条）

1. **声音没定就做全片** → 4 个项目都返工过（见第九节）。全片之前先出 30～60 秒声音样片，让主理人点头。
2. **把指令当结果**：给模型写了 děi，就以为它读的是 děi。判断只看实际声音（工厂001 交付了 5 句错音）。
3. **必须义的「得」(děi)**：本地开源模型发不出，会读成 dé。改写成「必须 / 一定要 / 就要 / 还要」。
4. **多音字按词典取音会错**：冲着、运转、去量、一场、撑得住、长约、上调、剪刀差……配音前过 `video:lint`，合成后看逐句拼音的读音表。
5. **回听「全部通过」≠ 读音全对**：语音识别听不出声调，分不清 de / dé / děi。交付时要说明这个盲区。
6. **阿拉伯数字不能直接给配音模型**：2025 读成两千零二十五，10% 读成十 percent，「百分之 twenty six」。全部先转中文读法。
7. **英文缩写逐个验证**：AI 读成「爱」、L / Z 读不准、句末的 AI 被吞。
8. **重复音节 / 吞字**：长句、叠字、「约是」最容易出。句子 ≤ 40 字，两个标点之间 ≤ 20 字。
9. **句尾最后一个字被截断**（ZipVoice）：慢一点生成再保持音调加速；句尾淡出。
10. **孤字和短标签折行**：最后一行只剩一个字、「巴菲特」折成两行。看关键帧拼图，质检要能报出来。
11. **画面里写死时长**：片子 9 分钟，标签写「这十分钟」。不写具体时长。
12. **配乐自己没单独听过**：代码合成的鼓声带「电波吱吱」杂音，是主理人听出来的。混音前单独听配乐。
13. **版权音乐 / AI 图里的字**：周杰伦原曲不能用；AI 画的中文常是错字。原创配乐，文字全部后叠。
14. **AI 生成标识**：视频号、抖音发布勾选「内容由 AI 生成」（《人工智能生成合成内容标识办法》2025-09-01 施行）；财经内容口播和画面都要有免责声明。
15. **被指出问题先查成品**，不要先拿词典、规则去解释（工厂001「总得」事件）。

## 一、多音字、变调、轻声（语音识别听不出来，靠读音表 + 人耳）

| 现象 | 例子（项目） | 根因 | 现在的防线 |
|---|---|---|---|
| **模型发不出 děi** | 「你总得知道」「就得回答」「还得看」「你得知道」，指令写 děi，成片全读 dé（工厂001，5 句，已交付未重做） | 模型弱音节：读 dei3 和读 dé 的频谱距离 10.6，小于同一个音重读两次的自然差别（18～32） | `video:lint` 报 ⚠；工厂 `pron.py` 的 `WEAK` 直接拦。写稿就不写必须义的「得」 |
| 预检漏掉名词后的「得」 | 「过去设计师得找参考」是必须义 děi，`video:lint` 只认「总得 / 就得 / 你得」这类前字，没报（婚庆片，配音前发现） | 规则只列了前面的字，没看后面跟的是不是动作 | `video:lint` 加第二支：「得」后紧跟找、做、写、改、先、去等动作就报（排除觉得、值得、变得）；稿里改成「要」 |
| 「得」按词取错 | 「传得最广」「涨得比你快」读成 dé（应为轻声 de，工厂001）；「撑得住」读成 dé（工厂002） | 词典按单字或按词取音，不看语境 | 坑词表 + 读音表人工按语境审 |
| 其他按词取音错 | 冲着 chōng（应 chòng）、运转 zhuàn（应 zhuǎn）、去量 liàng（应 liáng）、付了 liǎo（应 le）、稳固地 dì（应 de）、本视频为 wèi（应 wéi）、一场 cháng（应 chǎng）（工厂001） | 同上 | `video:lint` 的 `TRAPS`；项目读音覆盖表 |
| 词典切词把副词切进名词 | 「公司都会经历」切出「都会」读 dū huì；「慢慢地」的「地」读 dì（婚庆片，读音核对表在合成前发现） | 合成词典正向最长匹配 | `TRAPS` 加「都会」「慢慢地」；项目 `pronounce.tsv` 覆盖 |
| 行业词读错 | 长约 / 长鑫 / 长单读 zhǎng（应 cháng）；上调 / 下调读 diào（应 tiáo）；剪刀差读 chà（应 chā）（存储） | 拼音库和合成模型都不懂行业词 | 存储 `pronounce.tsv`：「待确认」不为 0 就拒绝合成 |
| 分词切错 | 「周一只让海力士跌了 3%」被切成「周 / 一只」（存储） | 词典最长匹配 | 覆盖表加「周一」「只让」 |
| 「一」「不」变调没做 | 一样、一间读 yī；一路、一千、一根没变调（工厂001、蕲春） | 各模型对变调的处理不一样 | Matcha：程序按规则变调；MeloTTS：按词手写声调（`voiceover.json` 的 `lexicon`） |
| 三声连读不自然 | 好友、也走（蕲春） | MeloTTS 不自己做三声变调 | 手写成 2 3；Matcha 交给模型（训练时就这么标）。**换模型必须重新确认谁负责变调** |
| 「了」读错 | 单独念「他跑了」成了「他跑累」（微电影） | 短句没有上下文，轻声读成实字 | 改成「于是，他跑了。」；3 字以内的句子和前后合并 |
| 轻声读太轻 | 「连着一间」的「着」几乎听不见（工厂001） | 轻声虚词本来就轻 | 改写（就是一间） |
| 人名读错 | 李录的「录」声调、格雷厄姆的「厄」（工厂001）；曹堪宇、陈福阳（存储） | 人名不在词典或按常见字读 | 人名、机构名第一次出现就进读音覆盖表 |
| 读音「争议」被当成借口 | 「总得」先被归为「听感分歧」，加了「争议读音」机制（工厂001） | 没去听成品，拿词典解释 | 撤掉；先查成品证据（第九节） |

## 二、数字、英文、符号

| 现象 | 例子（项目） | 根因 | 现在的防线 |
|---|---|---|---|
| 数字读法乱 | 「中国制造2025」读两千零二十五、「约2000人」被当年份逐位读、「10%」读十 percent、「2000万」读二千万（工厂001）；「百分之 twenty six」（存储 v2） | 模型自带数字规则不可靠，年份规则放太宽 | 送进模型前统一转中文：年份逐位读、百分之、千万亿前读「两」。存储 `numcn.py` 剩一个阿拉伯数字就拒绝合成；`video:lint --tts` 报 ✗ |
| AI 读成「爱」 | 交给英文引擎读（工厂001） | 模型英文不稳 | 字母用中文音节读（A 读 éi、I 读 āi）；存储写成「A I」 |
| 句末 AI 被吞 | 「聊 AI。」「学 AI」「这一轮 AI 行情」听成「艾」「爱爱」「哀」（工厂002） | AI 在句末或紧贴别的字时读不清 | AI 后面接词（AI 的事、AI 热潮）或改「人工智能」；`video:lint` 报 ⚠ |
| AI 紧贴逗号也被吞 | 「而是利用 AI，帮这些……」ZipVoice 3 次都听不到 AI，Matcha 读成「aai」（婚庆片样片） | 逗号前和句末一样是收尾位置 | `video:lint` 把逗号、顿号、分号、冒号前的 AI 也报 ⚠；改成「AI 工具，」 |
| 有的字母读不准 | L、Z 怎么写都不准，MBA 0/3（工厂，Matcha） | 模型上限 | 稿子里禁用，改中文（LLM → 大语言模型）；新缩写先跑 `video:letters` 验证 |
| 英文被整个跳过，回听还报通过 | 「利用 A I，」Matcha、ZipVoice 输出里都没有 AI（ZipVoice 那句时长和删掉 AI 的句子一样），Paraformer 回听只按汉字拼音比对，报 ✓（婚庆片样片） | 两个模型的词典都没有英文字母，OOV 只在 stderr 打一行就丢掉，而那行被 `grep -v OOV` 滤掉了 | 项目 `tts.py` 给词典补 A / I 的中文音节，合成前检查英文词都在词典里，不在就拒绝合成；`asr_check.py` 加「稿子里的英文缩写必须听得到」；**不要过滤 OOV 警告** |
| 大写字母被当音素符号 | S、T、W、Y（工厂，Matcha） | 模型音素表里有这些大写字母 | 字母一律映射成读法，不直接送字母 |
| 英文名念不顺 | Tim、EOE（微电影）；Rosenblatt、Counterpoint（存储） | 中文模型读英文 | 写成「提姆」「E O E」；能换中文就换（《证券分析》不写 Security Analysis） |
| 回听误报英文 | 「C E O」拆读被报成「冒出英文」（存储） | 比对时没把拆读合回去 | 修了 `asr_check.py`；看报告时先排除这类 |
| 符号被读出来或吞字 | 「·」「《》」（工厂001）；4F²（存储写成「四F平方」） | 模型对符号没规则 | 程序去掉或改写成中文；`video:lint` 报 |

## 三、配音的偶发故障（读音规则没错，模型随机出错；靠回听 + 重读 + 改写）

| 现象 | 例子（项目） | 根因 | 现在的防线 |
|---|---|---|---|
| 重复音节 | 「套利」读成「套号利」、「缩缩水」「一层层层」「复利前前提」（工厂001）；「对对风险」「险险跟」「学学爱」（工厂002） | 模型随机性；长句、相同或相近音节挨着更容易出 | 每句回听，不对就重读（原样 3 次 → 微调语速 2 次 → 拆短句 3 次）；8 次不过就改写稿子；噪声强度 1.0 → 0.667 |
| 「是」重复 | 「大约是 65 倍」读成「大约是是」（工厂002） | 「约」「是」挨着 | 去掉「是」 |
| 串音 | 「世界秩序」听成「世界继续」，「传得最广」多出一个音（工厂001） | 特定词组上的硬伤 | 8 次不过就改写（量世界格局、流传最广） |
| 吞字 | 「拿这几条原则」吞「几」，「永远要留」吞「要」（工厂001） | 同上 | 重读或改写 |
| 句尾被截断 | 最后一个字没读完（存储，ZipVoice） | 按目标语速直接生成时句尾时长不够 | 0.95 倍生成再保持音调加速；句尾 0.04 秒淡出；句尾还在高音量就放慢重来 |
| 合成阶段比成片复核松 | 合成时放行的 4 句，成片复核没过（工厂002） | 合成阶段「两个识别模型有一个听对就算过」 | 合成阶段和成片复核用同一个标准（以 SenseVoice 为准） |
| 回听对多音字是盲的 | 「73 句全部通过」，其实 5 句「得」读错（工厂001） | 识别模型输出汉字，dé / děi 都写「得」 | 报告里写明盲区；多音字靠读音表 + 人耳 |

## 四、声音选择与音质

| 现象 | 项目 | 根因 | 现在的做法 |
|---|---|---|---|
| 男声「怪」、有口音 | 工厂001 第一版（Kokoro） | Kokoro 中文带口音 | 换 Matcha 中英（标准普通话女声） |
| 配音「有口音、有点呆」 | 微电影第一轮（Kokoro 58 号） | 同上 | 45 个男声用识别模型筛出 4 个候选 → 最后用本人声音克隆 |
| 「读法不自然、重音不对」 | 蕲春 v2（Kokoro） | 同上 | v3 换 MeloTTS，韵律更自然 |
| 换了 4 轮声音 | 存储：Kokoro sid65 → 本人克隆 → 「不用本人声音」→ sid100 / sid60 → 定沉稳男声 sid60 | **没先问清楚要什么声音** | 需求卡第一项问声音；样片定声音 |
| 声音发闷 | 工厂（Matcha 16 kHz） | 采样率低 | 导出升到 48 kHz；要更好只能云端配音或真人 |
| 克隆声音不像 | 微电影（相似度 0.78） | int8 小模型 | 全精度模型 16 步 + 按原声频谱 EQ + 高频补偿 → 0.87 |
| 本人声音的隐私 | 微电影、存储 | 声音是个人生物信息 | 参考录音和合成结果不入库（`.gitignore`）；频道音色默认不用本人声音（存储的决定） |
| 想要「爆款解说腔」用不了 | 存储（微软「云希」） | 云环境拦了 `speech.platform.bing.com` | 要么在环境里放行，要么用剪映 / 云端付费音色重配 |

## 五、画面和字幕

| 现象 | 例子（项目） | 根因 | 现在的防线 |
|---|---|---|---|
| 孤字 | 「…不多花**钱**」最后一行只剩一个字（工厂001） | 文字刚好多一个字 | 自动查孤字，改短文字，不缩字号硬塞 |
| 带强调词的孤字漏查 | 「还是吹泡沫的人？」只剩「人？」（工厂002） | 检查只看纯文字元素 | 质检改成逐字取位置 |
| 短标签折行 | 「巴菲特」折成「巴菲 / 特」（工厂002） | 栏宽写死 | 6 字以内不许折行；栏宽自适应 |
| 质检误报折行 | 「65倍」数字和「倍」字号不同被当两行（工厂002） | 按顶边判断同一行 | 按上下是否重叠判断 |
| 大引号压字、全角逗号太宽 | 引号压在引导语上；「目标 ，还是」有空隙（工厂001） | 绝对定位；宋体全角标点 | 引号单独占位；标点半宽 |
| 标签写死时长 | 片子 9 分钟，标签「这十分钟」（工厂001） | 改时长没改文案 | 画面文字不写具体时长 |
| 字幕拆开英文 | 「MBA」被切成「M」「BA」两条（工厂001） | 按字数硬切 | 英文和数字整体不拆；`video:final --srt` 报 ✗ |
| 字幕超一行 | 长句没有标点可断（工厂） | 口播稿没逗号 | 两个标点之间 ≤ 20 字；`video:lint` 报 |
| 画面空档 | 6 秒以上没有新元素，观众走掉（粤语） | 一页口播太长 | 粤语管线报「画面空档」；`video:final` 报「6 秒不动」 |
| 章节时间戳对不上 | 发布包按估算写章节（存储） | 配音后时长变了 | 章节和简介按实际配音时间轴生成（`chapters.mjs`） |
| 内部叫法上了画面 | 章节名用了内部代号（存储） | 写给自己看的名字直接上屏 | 章节名用观众听得懂的话 |
| AI 图里的中文是错字 | 粤语 sketch 插画 | 文生图不会写中文 | 插画里不要字，文字全部用代码叠 |
| AI 视频角色漂移 | 微电影选路线时的评估 | 每段 5～10 秒独立生成 | 要角色一致就走程序化动画（同一份角色代码画每个镜头） |
| 片尾署名看不清 | 蕲春 | 背景太亮 | 片尾压暗 |

## 六、配乐与混音

| 现象 | 项目 | 根因 | 现在的做法 |
|---|---|---|---|
| 配乐有持续「吱吱 / biu biu」电波声 | 存储 v1 | 底鼓按「频率 × 绝对时间」算相位，每拍一次扫频 | 底鼓按单拍积分相位、去掉噪声滴答、整条低通。**混音前单独听 10 秒配乐** |
| 片头空口播导致检测报错 | 存储 | 片头只有音乐没有口播，冲击音检测拿到空段 | `@pause` 段单独处理 |
| 响度不统一 | 各项目 | 每个项目各自混 | 统一 -14 LUFS、真峰值 ≤ -1 dBTP；`video:final` 检查 |
| 想用流行歌 | 蕲春（周杰伦《本草纲目》） | 没有授权 | 不用原曲的录音、旋律、歌词；原创同风格节拍 |

## 七、内容、版权与合规

| 现象 | 项目 | 做法 |
|---|---|---|
| 煽情句被主理人删掉 | 微电影第二版 | 不写煽情句，用具体细节（「周四」开会、螺蛳粉火锅撸串） |
| 封面和文案不戳痛点 | 存储 | 封面写观众的损失和疑问（「−26% 真凶不是长鑫」） |
| 前 30 秒留不住人 | 普通话投研栏目 EP04（点击率 3.4%，0:24 流失过半，据成果中台记录） | 前 30 秒给结果、反转和这期要回答的问题；不开场自我介绍、不放目录页 |
| 单一来源的数字 | 存储 | 事实台账，每个数字挂编号；单一来源加「据……」 |
| 引文冒充原话 | 工厂 | 转述标「据 XX 整理」；史实标出处（同仓库规则 5） |
| 财经合规 | 工厂、存储、粤语 | 不荐股、不说目标价、不预测点位；口播 + 画面都有免责声明；画面和简介不放链接、二维码、微信 |
| 示意数字被当真 | DRAM（3:1 拨晶圆的示意比例） | 示意图标「示意」，口播不把示意百分比当市场数据讲 |

## 八、工程与环境

| 现象 | 项目 | 做法 |
|---|---|---|
| 并行渲染反而更慢 | 蕲春（4 核） | 4 核机器上 Chromium 单进程渲染 |
| 本地服务端口冲突 | 蕲春 | 端口由系统分配 |
| 整片重渲浪费时间 | 蕲春（一个画幅 1～1.5 小时） | 只重渲受影响的时间段再拼接（v2 片尾就是这样修的） |
| 改一句重配全片 | 各项目早期 | 逐句缓存，只重配改过的句子 |
| 大文件进了仓库 | 短片（21 MB 成片在 `dist/`）；存储（`__pycache__` 进了提交） | 成片、模型、缓存都放 `out/` 等忽略目录；提交前看 `git status` |
| 新会话模型没了 | 所有云端项目 | 云端容器是临时的，`.cache` 换会话就清空。常用模型写进环境的 setup script |
| 网络被拦 | 微电影、存储（Edge TTS、fal、Replicate、HuggingFace） | 先查环境网络策略（`read_documentation` → environment.network）；模型从 GitHub Release、npm 包、PyPI 拿 |
| YouTube API 上传被锁成私享 | 存储 | 未审核的 API 项目上传的视频会被锁私享；先手动上传或走审核 |

## 九、流程上的教训（返工的根因）

| 教训 | 出处 | 现在的关卡 |
|---|---|---|
| **声音、风格没确认就做全片**，做完才发现不对，全片重配重渲 | 工厂001、微电影、蕲春、存储 | G0 需求卡问清声音；G3 声音样片确认后才做全片 |
| **对结果负责，不对指令负责**：写了 děi 就当它读了 děi | 工厂001 | 判断只看实际声音：人耳、声学对比、能分辨差别的检查 |
| **被指出问题先查成品**，不先拿词典解释、不往「听感」上推 | 工厂001 | 第一步永远是拿成品证据 |
| **敢挑战，但只凭证据**：主理人也可能口误，用成品证据直接指出 | 工厂001 | 没证据不反驳 |
| **检查有漏网就先修检查**：先让质检能报出来，再修内容 | 工厂002 | 每次新错都落成规则 |
| **检查方法本身要验证**，交付时写明它查不到什么 | 工厂001 | 汇报模板里有「没查到的」 |
| **审过的读音必须入表**，不入表下一期再错一遍 | 工厂 | 读音覆盖表 + `TRAPS` |
| **宁可改稿，不留隐患**：8 次重读都不过，就是模型硬伤 | 工厂 | 改写，不赌运气 |
| **能复用就复用**：数据、配音、配乐、画面模式都别重做 | 蕲春 | 开工先找已有管线 |
| **动手前报步骤和预计用时**，中途变了主动说 | 蕲春 | 汇报模板 |

## 十、主理人偏好（每次都适用，有新的就加）

- 效率优先：能复用就复用；不要整片重来。
- 文案要轻、要具体，不煽情；图上不放账号名和说明小字（小红书 E01-v4）。
- 封面、标题戳痛点；章节名不用内部叫法。
- 频道解说默认不用本人声音（存储 2026-10-18 的决定）；个人作品可以用本人声音克隆（微电影）。
- 不用有版权的音乐和图片。
- 财经内容只讲「他怎么想」，不讲「买什么」。
