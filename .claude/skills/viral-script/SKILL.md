# 爆款脚本

完整方法论和逐句拆解在 `docs/content-factory/爆款结构.md`，以那份为准；样板是 `factory/episodes/001-lilu-columbia/episode.mjs`。

## 写稿前

1. 拿到**完整**素材（官方全文 > 带字幕视频 > 至少两份媒体整理稿互相对照），填拆解卡：原话（标出处，转述标「据 XX 整理」）、数字、有争议的观点、和观众生活的连接点。
2. 定**主钩子**：一个二选一问题，常驻标题栏（「你是目标还是代价」）。
3. 定 **5 个章节名**：每个都是让人想点开的怪词或反差词（「神的IPO」「用筷子的人」「教堂赌场」）。
4. 找出**全片最出圈的一段**，放在约 2/3 处，开头先预告。

## 结构（每一行都要有，顺序不变）

| 时间 | 段落 | 要求 |
|---|---|---|
| 0:00 | 冷开场 | 全片最有张力的一句原话 + 说话时的场景（「讲到 X 时，他停下来说了一句」） |
| 0:15 | 插话 / 细节 | 人物的一个小动作、补的半句、台下反应 |
| 0:25 | **共鸣桥** | 把这句话翻译成观众自己的经历（房子、账户、工作）。最关键，决定转发 |
| 0:35 | 时空定位 | 「这是 X 月 X 日的某地，某场合」，短句 |
| 0:45 | 传承链 / 来历 | 3～4 个年份串成一条线，证明他值得听；不念履历 |
| 1:10 | 观看框架 | 这场讲了什么、我们怎么看；埋一个开放问题（「有句话流传最广，放到后面讲」） |
| 1:30 | 五章正文 | 每章：原话 → 解读 → **落到你身上** → **一句话挂到下一章** |
| 末尾 | 12 条金句墙 | 每条 ≤ 16 字，截图收藏 |
| 最后 | 回扣 | 回到开头那句话，把问题抛给观众，引导评论；口播免责声明 |

## 写法规矩

- 段落之间用「但是」「所以」连，不用「然后」。
- 每 60～90 秒给一个新刺激：新画面、反转、数字、提问。
- 每页一个画面元素组合，元素用 `factory/README.md` 列出的类型；能用图解（对比、流向、时间线、房子曲线这类线条动画）就不用纯文字，动画只为帮助理解。
- 不开场自我介绍，不用目录页当钩子，不念履历，金句墙后不加新观点。
- 合规：只讲「他怎么想」，不讲「他买了什么你也买」；不预测点位涨跌；有争议的数字当场标注。
- 选题：主线素材在一个月以内；素材零散（社交媒体发言）时，用它做钩子，深度部分找同一人近一年的长访谈。人物持仓一律不点名。

## 为配音写稿（避免基础错误）

- 口播稿正常写汉字、数字、英文缩写；读音交给读音模块。
- 英文缩写避开含 L、Z 的（读不准），英文单词尽量换中文。
- 「AI」尽量不放句末、不紧贴后面的名词（「做 AI 算力」「AI 热潮」），容易读成一个音；需要时直接写「人工智能」。
- 不写必须义的「得」（总得、就得、还得、你得），这个模型发不出 děi，会读成 dé；写成「必须、一定要、就要、还要」。直接引语也照此改写。
- 踩过的坑见 `factory/错误档案.md`，写稿前扫一遍。
- 少用叠字和连续轻声（「一层一层」「连着」），关键句子短一点。
- 每句 ≤ 40 字左右，长句拆开；每句末尾要有标点，方便字幕断行。

## 写完

交给 `video-qc` 技能：`npm run video -- factory/episodes/<期> --no-video` → 修到全部通过 → 审读音表 → 出片。
